# Working on Finds

- This is a layer on the Shortlist engine. `vendor/shortlist/` is a pinned
  copy: never edit it here. Engine changes go to `nategk/shortlist` as
  generic features; then `npm run engine -- <ref>` re-pins (it also
  regenerates `api/`).
- `api/` is generated by `scripts/wrap-api.mjs`; don't hand-edit.
- Small changes (seed copy, rubric text, styling overrides, routine wording):
  merge to `main` and push without asking; open a PR and merge it right away
  so there's a record. Run `node --check` on touched JS and `npm test` first.
- Larger changes (enricher/crawler logic, anything touching data or
  credentials, engine re-pins): open a PR and ask before merging.
- `main` deploys to Vercel. Re-pinning the engine brings its `SHELL`
  version with it; `scripts/build.mjs` renames the caches to `finds-`.
- Facebook Marketplace is never crawled from the server; only the signed-in
  Chrome routine (`routines/fb-refresh.md`), at a human pace.
- Live data is in the deployment's database. Use
  `vendor/shortlist/scripts/remote.mjs` (`SHORTLIST_URL`, `ADMIN_TOKEN`).
